## 2. D 填入后 R06 的真实行为

出厂算例（工作体积 2000 mL、搅拌 100 rpm、Np=0.35、ρ=1000 kg/m³、D=0.052 m）：

```
N  = 100 rpm ÷ 60 × 2π            = 10.4720 rad/s
N³ = 1148.37
D⁵ = 0.052⁵                        = 3.80204e-07 m⁵
P  = Np·ρ·N³·D⁵ = 0.35×1000×1148.37×3.80204e-07 = 0.15281 W
ε  = P ÷ (ρ·V) = 0.15281 ÷ (1000 × 0.002 m³)     = 0.0764 W/kg
```

- ε = 0.0764 W/kg > 黄线 0.05 且 ≤ 红线 0.1 → R06 判 **🟡 黄**，文案：
  「接近剪切红线，建议降速并人工复核。比功率 ε ≈ 0.08 W/kg（红线 0.1、黄线 0.05、推荐区 0.02–0.04 W/kg）。」
- 校验汇总 **红 0 / 黄 2 / 绿 16**（黄 = R06 + R16），**与第七轮计数完全一致**，只是 R06 变黄的原因从"缺参数"换成了"ε 超黄线"，导出配置单照旧不被拦（只有红色才拦）。
- 交叉核对：ε×ρ = 76.4 W/m³，而你依据的工业 CHO 罐 P/V 是 22–35 W/m³ → 本例约为其 **2.2–3.5 倍**，判黄与你的依据方向一致。
- 想落进推荐区（0.02–0.04 W/kg，即 P/V 22–35 W/m³ 的等效区间），2.0 L 大约需要 **64–81 rpm**；想正好对上你引用的 22–35 W/m³，则约 **66–77 rpm**。

## 4. D 落地后暴露出的三处参数冲突（都**没有**擅自改，等你拍板）

### 冲突① 「搅拌启动建议转速」分档与 ε 红线打架（最要紧）

`agitation_start_suggestion.bands_ml` 还是第一轮的旧经验值（≤1000 mL→80、≤1800→100、其余→120 rpm）：

| 场景 | 软件建议起步转速 | 该转速的 ε | R06 判定 |
|---|---|---|---|
| V = 900 mL | 80 rpm | 0.0869 | 🟡 黄 |
| V = 1500 mL | 100 rpm | 0.1019 | 🔴 **红（禁止使用该配置）** |
| V = 2000 mL | 120 rpm | 0.1320 | 🔴 **红** |
| V = 2400 mL | 120 rpm | 0.1100 | 🔴 **红** |

也就是说：软件一边在结果区建议"120 rpm 起步"，一边在 R06 判它红色禁止 —— 自相矛盾。
可选处理（我按你选的做，也可以给别的数）：

- **方案 A（推荐）**：把分档改成 ε 推荐区反解出来的值 —— ≤1000 mL→55 rpm、≤1800→65 rpm、其余→75 rpm（对应各体积基本落 0.02–0.04）。
- **方案 B**：分档只保留"低速起步"含义（例如统一 60 rpm），并在①页把建议与 R06 判级并排显示。
- **方案 C**：不动分档，只在界面把"建议转速"改成"参考值，务必以 R06 的 ε 判定为准"（说明书我已经加了这句提醒，界面文字还没改）。

### 冲突② R05 允许的搅拌转速下限（80 rpm）在小体积时整段超红线

`process_defaults.agitation_rpm` 允许范围是 80–150 rpm，但 D=0.052 m 下 600 mL 的红线转速只有 **73.2 rpm**：
即"合规的最低转速"仍然超 ε 红线 → 600～1000 mL 工况下 R06 必然红/黄，R05 与 R06 互相夹住，用户没法两全。
可选：**下限放宽到 40–50 rpm**（与②硬件配置页/`process_defaults` 一起改），或确认小体积就是不允许高速（那 R06 报红即为正确行为）。

### 冲突③ R06 文案在 0.04 < ε ≤ 0.05 区间说反话

这段判 **🟢 通过**，但提示文字写的是"低于推荐区，剪切可能偏弱"，实际是**高于推荐区上限但未达黄线**。
一行文案的事，但它在校验输出里，属于"校验逻辑"范围，所以本轮只报告没改。你说改我就改成"高于推荐区但未达黄线，建议按低速复核"。

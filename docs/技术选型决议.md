# 技术选型决议（第一轮）

## 结论：PySide6（Qt for Python），不选 Streamlit

## 理由
1. **双击 .exe 是硬约束**：PySide6 + PyInstaller 是成熟的单 exe 桌面打包路径；
   Streamlit 本质是"本地 Web 服务器 + 浏览器"，打包需要额外捆绑服务进程，
   易出现端口占用、浏览器自动打开失败等问题，对零代码用户不友好。
2. **彻底离线、无本机端口**：Streamlit 默认监听 localhost 端口，可能被安全软件拦截；
   Qt 原生桌面程序完全无网络痕迹，符合"不联网、不上传"约束。
3. **表单+即时校验的交互模型更稳**：本软件核心是"填参数 → 实时出 18 条红黄绿校验结果"，
   Qt 信号槽可以在输入变化时增量刷新；Streamlit 每次交互整页重跑脚本，
   SOP 勾选清单、模板复用等状态管理会明显别扭。
4. **桌面原生能力**：原生文件对话框（导入 my-Control CSV）、菜单、可勾选清单、
   多批次对比表格，Qt 都是成熟范式。
5. **授权**：PySide6 为 LGPL（PyQt 为 GPL/商业双授权），内部工具两者皆可，PySide6 更省心。
6. **图表**：matplotlib 嵌入 Qt 控件成熟（第四轮生长曲线使用）。

## 代价（如实告知）
- GUI 代码量比 Streamlit 大，前两轮开发速度略慢；对 5 个模块的中小型应用可接受。
- 备选方案：若后续更看重"开发快、随时改"而放宽 .exe 体验，可退回 Streamlit，
  但需用户明确放弃"双击即用"的严格要求。
